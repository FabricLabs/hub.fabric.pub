Privacy Policy — Fabric Passport

Product: Fabric Passport (@fabric/passport), a Chromium extension
Operator: Fabric Labs
Effective: 26 October 2026
Contact: security@fabric.pub

This policy describes how Fabric Passport handles information on your computer and what, if anything, leaves the extension. It is written to satisfy the Chrome Web Store User Data Policy, including Limited Use.

The use of information received from Google APIs will adhere to the Chrome Web Store User Data Policy, including the Limited Use requirements.

1. What this extension is

Fabric Passport is a local cryptographic identity wallet. It lets you create or restore a Fabric identity, sign in to Fabric websites (Passport v2: you approve each sign-in for the site your browser shows), mutually link devices and desktop apps, and use Bitcoin keys from the same seed against a Fabric Hub you choose. Each account has a separate identity key, wallet keys, and escrow (cosigner) key, so signing in doesn’t reveal your wallet.

Fabric Labs does not operate a cloud account for Passport. There is no Passport signup with us. We do not receive your seed phrase, wallet password, or private keys.

2. Information handled on this device

The following is stored in Chromium extension storage on your machine (encrypted at rest with AES-GCM where the implementation encrypts wallet material):

Category What Leaves this device?
Authentication information Your master extended private key, sealed with AES-GCM under your lock password (the seed phrase and BIP39 passphrase are not kept after import) No (unless you export an encrypted backup yourself)
Personally identifiable information Fabric identity public key / id of each account; optional display labels you type An identity public key is sent only to Hubs you connect to or sites you approve a sign-in for
Financial and payment information Bitcoin addresses and wallet xpubs derived from your seed; optional Lightning invoice you choose to pay Sent to the active Fabric Hub you configured when you use Wallet features. A website gets a wallet xpub or your escrow key only if it asks and you tick that item on the sign-in prompt
User activity Last-activity timestamp; coarse request counts and Content-Length sums for trusted Hub origins only No — kept in memory / local storage for the extension UI
Web history (narrow) Origins of Fabric Hubs you Connect & register; the origin of a sign-in or device-link you are asked to approve; desktop apps you linked Shown to you in the approval UI; kept locally

Passport does not collect health information, location, general browsing history, page HTML, cookies from unrelated sites, or advertising identifiers.

The content script runs on HTTPS pages (and listed loopback Hub ports) so a Fabric site can hand it a sign-in challenge or device-link request. It does not scrape the page. It ignores messages that are not Passport sign-in, device-link, or Hub mesh-bridge messages.

3. Information sent to other computers

Passport talks to the network only when you use a feature that needs it:

  1. A Fabric Hub you choose (default public hub https://hub.fabric.pub, or a local/self-hosted Hub, or another allowlisted HTTPS hub). Examples: network status, WebRTC peer registration, device-link signatures, optional Bitcoin or Lightning calls through that Hub’s HTTP API.
  2. The website that asked you to sign in, only after you click Sign in (or Approve & link). Passport hands the signed answer back to the page; the page sends it to its own server. It holds a BIP340 signature, the identity public key of the account you picked, and only the extras you ticked — never your seed or private keys.
  3. A desktop app you linked (Fabric Hub or GoonCitizen on this computer, over 127.0.0.1), only when you choose to sign in with it. Linking shows the same six-digit code in both places.
  4. Chrome / Google as part of installing or updating the extension from the Chrome Web Store. Fabric Labs does not receive that telemetry.

Cleartext http:// is allowed only for loopback (localhost / 127.0.0.1) so you can develop against a local Hub. Public hubs must be HTTPS.

We do not sell user data. We do not use user data for advertising, credit-worthiness, or lending. We do not transfer user data to data brokers.

Hubs you connect to are independent operators. Their own privacy practices apply to what they log. Fabric Labs operates hub.fabric.pub; other hosts are not this extension’s publisher.

4. Why we request permissions

Permissions exist so Passport can keep keys on-device, show an approval prompt, inject a small content script for Fabric postMessage, keep a WebRTC offscreen document alive for Hub mesh, and (only after Connect & register) attach a public X-Fabric-Identity header on requests to that Hub.

5. Retention and deletion

Local data remains until you remove the identity in Passport settings, clear extension storage, or uninstall the extension. Uninstalling Passport deletes Chromium extension storage for this item on that profile. We cannot remotely delete keys we never received.

6. Children

Passport is not directed at children under 13 (or the applicable age in your country). Do not use it to store a child’s identity.
